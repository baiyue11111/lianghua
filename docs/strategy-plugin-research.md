# 策略插件研究结论

日期：2026-10-04。状态：研究与设计建议，尚未实现新接口。

## 决定

沿用本项目已有内核、账户和市场模块。统一采用一个策略文件、一个参数类、一个策略类。系统通过固定接口加载文件，不维护策略名称名单，不写按策略名称分支。

策略负责选什么、何时改变仓位、目标权重是多少。系统负责准备数据、按市场规则计算订单、成交、记账和记录。共享指标和权重函数可以复用；不把每个策略强制拆成多个插件。

本项目现阶段是股票组合研究。统一输出目标权重适合这一范围，不宣称它已经覆盖期权组合、盘口做市和特殊订单策略。

## 原始资料和取舍

1. [VeighNa CTA文档](https://github.com/vnpy/vnpy/blob/master/docs/community/app/cta_strategy.md)：独立策略目录、同一策略多个参数实例、参数和运行状态分离。采用这些边界；不采用模板中完整引擎对象暴露给策略的做法。
2. [VeighNa模板源码](https://raw.githubusercontent.com/vnpy/vnpy_ctastrategy/main/vnpy_ctastrategy/template.py)：配置覆盖声明参数，状态变量按实例复制。我们的参数需更严格：未知字段和错误类型报错，不静默忽略。
3. [Backtrader Strategy](https://www.backtrader.com/docu/strategy/)及[参数机制](https://www.backtrader.com/docu/concepts/)：引擎推动策略、参数用于实例化、订单结果通过事件通知。采用引擎驱动和实例隔离；当前组合研究先保留一个决策入口，不预建大量空回调。
4. [Cockburn：Ports and Adapters](https://alistair.cockburn.us/hexagonal-architecture)：业务通过接口与外界交换数据，可独立测试。采用明确数据契约，策略不依赖数据库、HTTP、界面或券商实现。
5. [Fowler：Dependency Injection](https://www.martinfowler.com/articles/injection.html)：装配与使用分开。采用一个装配入口，向内核传入对象；不增加依赖注入容器。
6. [QuantConnect框架](https://www.quantconnect.com/docs/v2/writing-algorithms/algorithm-framework/overview)：模块职责明确，目标仓位进入执行层。文档也指出默认等权模型可能导致意外集中和换仓；采用职责边界，不照搬强制五模块结构。
7. [Python importlib](https://docs.python.org/3/library/importlib.html)：用标准模块导入机制加载本地策略，无需引入插件管理框架。

这些资料支持接口隔离和参数实例化；“单文件”和下述具体接口是本项目的设计选择，不是统一行业标准。

## 本项目已经有什么

已直接阅读当前工作区，未依赖历史说明判断实现状态。

- `src/lianghua/core/interfaces.py`：已有 Strategy、Allocator、RiskModel、MarketAdapter 等 Protocol。
- `src/lianghua/core/kernel.py`：已有依赖传入、数据契约检查、先执行前期订单再计算当前决策的顺序。
- `src/lianghua/plugins/strategies/breadth_low_amount_reversal.py`：已有单文件策略及不可变参数类，但指标名固定为 ma120、r20、amount20，换仓日由 frame.context 传入。
- `src/lianghua/config.py`：配置哈希目前只覆盖资金、研究级别、策略名称；不能作为完整参数运行身份。
- `src/lianghua/strategies/` 和 `src/lianghua/plugins/strategies/`：同名策略存在两条接口路径，分别返回 TargetPortfolio 和 SignalSet。旧路径对多项参数强制限定原值。
- `src/lianghua/cli.py`：策略名单写死，run 入口主动阻止生成未经验证的收益。
- `src/lianghua/research.py`：旧 runner 包含固定窗口指标和按策略属性取默认值的行为。

局部验证：现有 core 测试 9 项、CN_EQUITY闭环测试 4 项通过。它们验证当前代码，不代表拟议接口已经落地，也不代表真实历史收益通过验收。

复现实验：非换仓日、账户持有 A/B 时，策略返回两个 hold 信号；EqualWeightAllocator(1) 输出 A=0.5、B=0.5。接口没有“不改变目标”的表达。若实际市值权重已偏离 50/50，就可能再次规划调仓。

另外，当前等权分配的分母是实际选中数量，旧策略分母是目标持股数。例如目标8只却只选中4只，两者分别给每只25%和12.5%。迁移时必须保留原规则，不能静默改为满仓。

## 统一接口

保留现有类型和名称，修改当前 Strategy.generate 的返回值，不新增另一套长期并行接口。

```python
# 每个策略文件都声明以下两个类
@dataclass(frozen=True)
class Params:
    # 默认值、类型、单位、上下限、显示名称在这里声明
    ...

class Strategy:
    strategy_id: str

    def __init__(self, params: Params): ...

    def requirements(self) -> DataRequest: ...

    def generate(
        self, frame: MarketFrame, account: AccountSnapshot
    ) -> TargetSet | None: ...
```

`DataRequest` 是拟新增的公共请求结构；其它数据类型已有。上述是接口草案，不是可运行示例。

调用顺序：读取配置 → 导入模块 → 验证并构建 Params → 创建 Strategy → 取得数据请求 → 准备数据 → Kernel运行。只有装配入口知道模块路径，内核不知道具体策略类。

| 接口 | 明确约定 |
|---|---|
| Params | 不可变；未知键、错误类型、非有限数、越界值均报错。不自动把字符串转数字，不忽略拼错字段。省略参数时可使用已声明默认值，但运行记录必须保存补齐后的全部值 |
| DataRequest | 原始字段、历史长度、频率和价格口径；请求由已验证参数计算。不能修改窗口数值却继续提供旧窗口指标 |
| MarketFrame | 当前可见数据及只读历史；使用带时区时间、统一证券标识和单位；历史截止决策时间，财务数据按可用时间限制，信号价格与成交原价分开 |
| AccountSnapshot | 实际现金、权益、持股及可卖数量；不得把计划持仓当成已成交持仓 |
| TargetSet | 本策略账户的完整新目标权重；未列出的旧持仓目标为零；带 strategy_id、时间和决策原因。沿用 source_id表达来源，补充原因字段 |
| None | 此次没有新决策；不重算权重、不生成新调仓请求，未完成订单按原已声明执行规则继续处理 |
| 空 TargetSet | 明确将持仓目标设为零。系统按市场约束执行，不保证立即全部卖出 |

策略输出的是目标，不是保证成交的事实。同样输入必须给出同样输出；随机策略的种子是参数。初版采用连续运行、停止后重建实例；不承诺断点恢复或运行中修改参数。确需恢复时再增加明确的状态存取契约。

## 参数放在哪里

单文件包含参数定义和策略规则，运行配置保存实际取值。配置是数据，不是第二个策略实现。

| 所属 | 内容 |
|---|---|
| 账户配置 | 初始资金；首版每次运行一个策略账户。多策略资金竞争不在本次接口范围内 |
| 策略 Params | 看过去多久、排序指标和方向、目标持股数、换仓周期、入场/出场条件、仓位分配规则 |
| 数据配置 | 数据快照、股票池范围、时间范围、价格处理版本 |
| 市场及执行配置 | 交易单位、可卖约束、交易日历、费用、滑点、成交量约束及生效时间 |
| 系统计算结果 | 每只需要买卖多少股、成交多少、剩余委托和实际盈亏 |

如果策略本来规定固定每次买入数量，该数量属于它的 Params；若策略按目标权重运行，股数由系统算，不能再填一个独立股数与权重冲突。

不同策略不必有完全相同的参数。按市值排序只是某类策略支持的指标之一；系统提供数据字段，策略决定如何使用。不会给原反转策略新增市值筛选。

参数只声明一次。配置表单读取 Params 的字段元数据，前端不维护另一张策略参数名单。沿用现有 JSON 配置形式，不为此增加另一种配置语言。

示意配置（未来格式，尚未接入）：

```json
{
  "account": {"initial_cash": "100000"},
  "strategy": {
    "module": "lianghua.plugins.strategies.example",
    "params": {
      "positions": 8,
      "lookback": 20,
      "rebalance": "monthly"
    }
  },
  "data": {"snapshot": "<已验证数据快照>"},
  "market": {"rules": "<已有市场规则配置>"}
}
```

模块统一导出 Params 与 Strategy。导入失败、接口不符、数据不足立即报错；不按名字查找备用实现。只加载配置明确选择的本地模块，不自动运行目录里的所有文件。导入是执行本地Python代码，不构成隔离沙箱。

## 最小改动顺序

1. 先冻结现有策略规则与固定输入输出样本。明确不足持股数时的权重、月内是否交易、首次入场时间。
2. 在 core/contracts.py 中补 DataRequest 和目标原因；Strategy.generate 统一返回 TargetSet或None；Kernel及Recorder一并更新。公共权重计算留作纯函数，由策略调用；移除内核中强制 SignalSet→Allocator 的中转。
3. 建立单一装配入口，读取JSON、加载策略模块、验证Params及数据请求。完整有效配置进入现有配置哈希，代码哈希覆盖策略及共享计算依赖，数据哈希覆盖快照与处理口径。
4. 把一个现有策略迁到新接口，保留原参数作为基准配置。用窗口参数驱动真实计算，不再把ma120/r20写进通用数据契约。数据层提供所需历史，指标在策略中调用公共纯函数计算；可以缓存，但缓存键必须覆盖数据和参数。
5. 每迁完一条调用路径，删除被替换的旧实现和隐式默认分支；历史结果作为带原哈希的只读存档保留。最终只有一个策略目录和一个接口。
6. 配置表单读取同一参数定义。已有回测数据与账户验收门禁继续生效；接口完成后仍需验证真实数据接入，才能开放收益运行。

不新建完整回测框架、插件容器或跨语言运行服务。MATLAB可使用相同的数据概念，但执行.m文件需要明确的MATLAB运行边界；此次建议先落地现有Python系统，不把跨语言兼容混入第一版。

## 验收与A/B

固定数据、市场规则和账户输入，只更换待测策略或参数。结构变更的A/B目标是规则等价；参数实验的目标是确认参数影响预期环节，并不要求每个参数提高收益。

- A：原策略及原参数；B：新接口及相同参数。比较选股、目标、调仓时点、订单和账户结果。比较来源必须采用可验证输入；未经验证的旧收益不作为基准。
- 窗口从20改为40：数据需求和指标值都改变；运行身份也改变。若指标未改变，测试失败。
- 持股上限8改为12：选择上限变化；没有新增选股条件。候选不足时按该策略声明的资金规则执行。
- 非换仓日行情变动：无新决策，不能因权重漂移自动生成新订单。
- 保持不动、清仓、设置新目标：三种输出分别验证，不能混用。
- 同一文件两组参数连续或交错运行：实例状态不互相污染。
- 新增一个符合接口的策略文件并指向配置：核心代码、CLI和前端无需新增策略名分支。
- 坏参数、缺数据、未来时间输出：明确失败，无备用通道。
- 合同及核心变更：测合同、内核、市场连接和一个小闭环；接口稳定后，只改策略规则时运行策略合同测试及其固定样本。
- 消融：删除旧策略名单和强制分配中转后，同参数闭环仍能成立。通过后再删除旧路径，避免长期双实现。

完成标准不是“文件可以导入”，而是“新策略只加文件，调参不用复制文件，输入输出可独立测试，且同参数迁移不改变原策略规则”。
