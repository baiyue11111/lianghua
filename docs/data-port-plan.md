# 通用数据入口 Implementation Plan

> **For agentic workers:** 按模块执行，先写失败测试，再实现并独立验收。沿用用户已指定的前后端两名subagent；主agent负责真实数据接入和样本外策略。

**Goal:** 任意符合统一接口的策略可按参数请求数据，账户从实际交易计算费用和税费，前端可运行并比较结果。

**Architecture:** 策略Params产生DataRequest，数据适配器按范围、字段、历史长度及运行日期提供每日只读视图。账户处理成交、持有期和公司行动；数据不绑定策略参数。数据版本由系统记录，同一版本用于多组参数。

**Tech Stack:** 现有Python、DuckDB/Parquet、FastAPI、React和无端口浏览器验收。

**Spec:** `docs/data-port.html`及本轮已获用户“完整实现”的确认。

## Global Constraints

- 不新增策略名称分支、fallback或参数绑定的账户输入。
- 保留原反转规则及用户已有修改；不提交Git、不启动监听端口。
- 真实成交使用原价，信号使用事件生效后的复权指数；不得把复权因子当持股数量。
- 股息税政策与实际扣款时间分开：本次声明境内个人普通非限售A股，研究结算为卖出与股息到账两者较晚日期扣款，未卖出潜在税负单独列示。
- 不根据保留时段的收益选择参数，不以正收益作为工程验收条件。

## Review Focus

1. 参数增大但预热数据不足：明确拒绝，不继续使用旧窗口。
2. 未请求证券、未来行情、缺失字段：不得进入策略视图。
3. 卖出不足一月、跨自然月/年、部分卖出和多次分红：FIFO税基与现金分开核算。
4. 新策略改变参数后仍可复用原数据版本；前端不能显示旧结果冒充新结果。
5. 保留时段数据不是全市场；独立结果报告必须显示固定证券池及数据局限。
