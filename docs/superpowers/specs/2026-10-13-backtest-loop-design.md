# 固定回测内核、公共计算与可选参数更新

用户意图：Kernel 像训练/验证循环，是常驻驱动器；策略像可替换模型。一次运行可以不更新参数，也可以通过可插拔更新器重复运行。协议是唯一公共入口，前端保持原样。

## 边界

- `protocal.py` 负责请求、标准数据查询、组装、序列化和统一存储；不再计算绩效。
- `core/kernel.py` 驱动原子回测和可选外层参数更新，不识别具体策略或搜索算法名称，不读写文件。
- `core/calculation.py` 的公共类 `Calculation` 集中现有 SMA、等权、绩效和候选参数选择计算；不复制行业算法大全。
- 策略保留买卖判断、排名、调仓时机、预热行为；修改只替换重复数学计算，不能修改规则。
- 已有数据适配、税费及有状态结算插件仍保持原有职责；本次不把账户生命周期塞入公共数学工具，不拆散或重做此前数据插件。

## 单次路径

现有 `workbench.backtest` 不传 `search` 时恰好运行一次。每次创建新策略和新结算状态。计算评价进入 Kernel 并由可注入计算对象完成，输出指标随响应返回。默认评价口径保持当前结果：252 周期/年、逐期基准 0、样本标准差；显式参数可以修改年化周期及逐期基准。

## 可选参数更新路径

`Kernel.search(request, updater, *, max_trials, metric, direction, validation=None)` 反复调用更新器 `updater(trials)`，输入仅有已完成试验，输出新参数映射或 None（停止）。每个试验仍使用同一原子执行函数，但策略、结算和运行身份必须隔离。锁覆盖整个搜索，其他原子调用不能插入。

不强制反向传播，不内置策略分支，不自动重试失败候选。任一错误即停止并报告失败。有效分数必须是有限数值且非 bool；方向只允许 max/min，同分保留先完成者。

协议仍使用 `workbench.backtest`，可选 `search` 对象含更新方法声明、最大次数、指标、方向及验证日期。声明格式为 module:Class、method、params，组装一个接收已完成 trials 的 callable。内置 Calculation.propose 只顺序提出显式候选列表；其他类方法通过相同声明替换，无需改 Kernel 或协议分支。未提供搜索时不创建或调用更新器，不增加 frontend 文件或第二条 HTTP/CLI 路径。

验证区间必须严格晚于搜索区间。选出最佳参数之后验证恰好一次，验证结果不反馈给更新器，不参加排名。原子运行是指一次完整回测，不意味着磁盘多文件事务。

## 可审计输出

单次现有字段不删除。搜索响应包含每个试验的有效参数、运行身份、完整回测结果、分数、最佳试验身份和可选验证结果。所有成功试验和验证结果经同一个 DataBus 保存到 data/runs；搜索失败时，已完成试验不得消失，失败证据也经该总线保存。评价口径进入配置与哈希，改变评价口径不得改变成交或权益。

## 验收

默认单次的指标、权益和成交与改造前完全一致；改变参数能改变策略结果；改年化/基准只改变评价。更新器只看到已完成试验；验证不会参与选择。锁及异常释放正确；无前端改动、无直接文件数据口、无兼容 wrapper 或 fallback。
