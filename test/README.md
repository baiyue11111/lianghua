# 固定业务回归用例

每个 case 固定策略配置、输入数据和预期结果。运行真实 CLI 回测后，逐项核对预期结果。

在项目根目录运行：

```sh
uv run python -m unittest discover -s test -v
```

## 目录

- `data/bars.csv`：固定行情，20 只证券，共 3140 条记录。
- `data/files.json`：固定交易日历、证券事实、复权因子、费用和税务政策。
- `data/quotes.json`：采集模块专项测试共用的固定报价请求与响应。
- `cases/<名称>/config.json`：与 `lianghua --backtest` 相同格式的固定配置。
- `cases/<名称>/input.json`：该用例对固定行情的明确修改；空列表表示直接使用原行情。
- `cases/<名称>/expected.json`：人工核对后保存的固定答案。
- `test_cases.py`：共用测试入口。新增 case 只需增加一个目录及以上三个文件。

输入由仓库已有工程行情固化而来，测试直接读取这里保存的文件。回测在临时目录中运行。

## 已有 case

| case | 检查内容 | 最终资产 |
| --- | --- | ---: |
| `breadth_slots` | 宽度择时策略只有 2 个候选，但配置 4 个持仓槽位；每只权重仍为 25% | 104298.90824 |
| `moving_average_hold` | 双均线买入后继续持有，已有持仓保持原数量 | 108973.27 |
| `moving_average_half` | 同一双均线策略，总仓位设为 50% | 104486.635 |
| `moving_average_exit` | 双均线转弱后，在下一个交易日卖出 | 108836.11 |

这些用例核对目标权重、成交日期、买卖方向、股数、成交价、各项费用、每日现金与资产、已实现与未实现盈亏、最终持仓、待成交订单数和全部回测指标。`null` 表示没有新决策，空权重 `{}` 表示清仓。

## 答案如何核对

以 `moving_average_hold` 为例：初始资金 100000；2 月 3 日买入 9000 股，成交价 11，买入金额 99000。佣金为 24.75，过户费为 1.98，余下现金为 973.27。2 月 4 日收盘价为 12，持仓市值为 108000，最终资产为 108973.27。

半仓用例买入 4500 股，佣金 12.375，过户费 0.99，最终资产为 50486.635 + 4500 × 12 = 104486.635。

卖出用例的卖出金额为 108000，佣金 27，印花税 108，过户费 2.16，最终现金为 973.27 + 108000 - 27 - 108 - 2.16 = 108836.11。

宽度择时用例沿用已有固定基线。两只证券各买入 2200 股，成交价均为 11.02。每笔买入金额为 24244，佣金为 6.061，过户费为 0.48488。余下现金为 100000 - 2 × (24244 + 6.061 + 0.48488) = 51498.90824，最终资产为 51498.90824 + 2 × 2200 × 12 = 104298.90824。

## 更新规则

金额与股数按十进制字符串精确比对。测试失败会显示实际结果与固定答案的差异。

`expected.json` 只在业务规则明确变更、重新核对答案后人工修改。测试入口没有生成或更新答案的功能。

这 4 个 case 覆盖上述行为；分红、税务结算、其他策略和研究会计模式仍由现有 `tests/` 中的专项测试覆盖。
